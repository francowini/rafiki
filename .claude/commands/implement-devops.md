# Implement DevOps

Implement a specific DevOps deliverable from a multi-mind deliverables document.

**Usage**: `/implement-devops [doc-path] [deliverable-number]`

**Examples**:
- `/implement-devops docs/telegram-tracking-deliverables.md 6`
- `/implement-devops docs/habits-feature-deliverables.md 8`

## Prerequisites

1. A deliverables document generated by `/multi-mind`
2. The deliverable must be of **Type: DevOps**
3. Backend/Frontend deliverables should typically be completed first

## Implementation Process

### Step 1: Read and Validate

1. Read the deliverables document at `[doc-path]`
2. Find the specified deliverable number
3. Validate:
   - Type is DevOps
   - Dependencies are satisfied

If the deliverable is NOT DevOps type, inform the user and suggest the correct command.

### Step 2: Read DevOps Guidelines

Before implementing, read:
- `devops/DEPLOYMENT_GUIDE.md` - Deployment procedures
- `devops/BACKEND_DEVELOPMENT.md` - Backend deployment patterns
- Existing Docker and deployment configurations

### Step 3: Analyze Existing Infrastructure

Based on the deliverable's technical notes, examine:
- `docker-compose.yml` - Service definitions
- `Dockerfile` - Container configuration
- `devops/deploy.sh` - Deployment scripts
- `devops/nginx/` - Nginx configuration
- `.env.example` - Environment variables

Use Read, Glob, and Grep tools to understand existing patterns.

## Error Handling

If issues are found:
- **Wrong type**: Suggest correct `/implement-*` command
- **Missing dependencies**: List which deliverables must be completed first
- **Infrastructure not ready**: Explain what needs to be set up first

## Tips for Safe DevOps

1. **Always have a rollback plan**: Document how to undo changes
2. **Backup before migrations**: Especially for schema changes
3. **Test in staging first**: If possible, verify changes locally
4. **Monitor after deploy**: Watch logs for unexpected errors
5. **Document secrets**: Note which secrets need to be added (but not their values)
6. **Keep deployments simple**: Use existing scripts when possible
