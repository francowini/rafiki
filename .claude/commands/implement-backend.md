# Implement Backend

Implement a specific backend deliverable from a multi-mind deliverables document.

**Usage**: `/implement-backend [doc-path] [deliverable-number]`

**Examples**:
- `/implement-backend docs/telegram-tracking-deliverables.md 1`
- `/implement-backend docs/habits-feature-deliverables.md 3`

## Prerequisites

1. A deliverables document generated by `/multi-mind`
2. The deliverable must be of **Type: Backend**
3. All dependency deliverables must be completed first

## Implementation Process

### Step 1: Read and Validate

1. Read the deliverables document at `[doc-path]`
2. Find the specified deliverable number
3. Validate:
   - Type is Backend
   - Dependencies are satisfied (check if previous deliverables are done)
   - Architecture compliance is confirmed in the document

If the deliverable is NOT Backend type, inform the user and suggest the correct command.

### Step 2: Read Architecture Guidelines

Before implementing, read these critical documents:
- `devs/business-model-dependencies.md` - Architecture rules
- `devs/errors-to-avoid-backend.md` - Common mistakes to avoid

### Step 3: Analyze Existing Code

Based on the deliverable's technical notes, examine:
- Existing domain code in `business/domain/`
- Business types in `business/types/`
- API handlers in `app/domain/`
- Database stores in `business/domain/*/stores/`

Use Read, Glob, and Grep tools to understand existing patterns.

## Errors-to-Avoid Compliance

Checklist from `devs/errors-to-avoid-backend.md`:
- [ ] No primitive types in domain models (use business/types/)
- [ ] Parse functions return errors, MustParse panics
- [ ] Database stores use toDBModel/toCoreModel pattern
- [ ] App layer parses primitives to strong types
- [ ] Proper error handling with predefined errors
- [ ] No CHECK constraints in database (validation in business layer)
- [ ] Delegate pattern for cascade operations
- [ ] One-directional imports (child → parent only)

## Implementation Checklist

- [ ] Create migration file
- [ ] Create business types (if new)
- [ ] Create domain model
- [ ] Create business logic
- [ ] Create database store
- [ ] Create app layer handlers
- [ ] Register routes in mux
- [ ] Test endpoints manually
```

### Step 5: Validate Against Errors-to-Avoid

After generating the specification:
1. Read `devs/errors-to-avoid-backend.md`
2. Check each code snippet against the documented patterns
3. Fix any violations before finalizing

## Output

Generate a single implementation file:
```
docs/[feature-name]-backend-d[N].md
```

Where:
- `[feature-name]` comes from the deliverables document filename
- `[N]` is the deliverable number

## Error Handling

If issues are found:
- **Wrong type**: Suggest correct `/implement-*` command
- **Missing dependencies**: List which deliverables must be completed first
- **Architecture violation**: Explain the issue and how to resolve it
```
