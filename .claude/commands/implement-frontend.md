# Implement Frontend

Implement a specific frontend deliverable from a multi-mind deliverables document.

**Usage**: `/implement-frontend [doc-path] [deliverable-number]`

**Examples**:
- `/implement-frontend docs/telegram-tracking-deliverables.md 4`
- `/implement-frontend docs/habits-feature-deliverables.md 5`

## Prerequisites

1. A deliverables document generated by `/multi-mind`
2. The deliverable must be of **Type: Frontend**
3. All dependency deliverables (especially backend) must be completed first

## Implementation Process

### Step 1: Read and Validate

1. Read the deliverables document at `[doc-path]`
2. Find the specified deliverable number
3. Validate:
   - Type is Frontend
   - Dependencies are satisfied (backend endpoints exist)
   - Architecture compliance is confirmed in the document

If the deliverable is NOT Frontend type, inform the user and suggest the correct command.

### Step 2: Read Frontend Guidelines

Before implementing, read:
- `devs/errors-to-avoid-frontend.md` - Common mistakes to avoid
- `devs/FRONTEND_DEVELOPMENT.md` - Frontend patterns and best practices

### Step 3: Analyze Existing Code

Based on the deliverable's technical notes, examine:
- Existing components in `frontend/components/features/`
- UI components in `frontend/components/ui/`
- API client in `frontend/lib/api.ts`
- Types in `frontend/lib/types.ts`
- Similar pages in `frontend/app/`

Use Read, Glob, and Grep tools to understand existing patterns.

### Step 4: Design Phase (Leverage frontend-design Plugin)

**IMPORTANT**: When implementing UI components, describe what you're building in natural language to activate the `frontend-design` plugin for distinctive, production-grade designs.

For example:
- "Build a modern card component for displaying [X] with visual polish"
- "Create a form for [Y] with elegant validation feedback"

This ensures the implementation avoids generic AI aesthetics and produces polished, creative code.

## Errors-to-Avoid Compliance

Checklist from `devs/errors-to-avoid-frontend.md`:
- [ ] Use 'use client' directive for client components
- [ ] Proper TypeScript types (no `any`)
- [ ] Form validation with Zod schemas
- [ ] Loading states for async operations
- [ ] Error boundaries for error handling
- [ ] Accessible components (ARIA labels, keyboard nav)
- [ ] Responsive design (mobile-first)
- [ ] Consistent styling with design system

## Implementation Checklist

- [ ] Create/update types in lib/types.ts
- [ ] Add API functions to lib/api.ts
- [ ] Create feature components
- [ ] Create/update page component
- [ ] Add route to navigation (if new page)
- [ ] Test on mobile viewport
- [ ] Test loading states
- [ ] Test error states
- [ ] Run `npm run lint` and fix issues

### Step 6: Validate Against Errors-to-Avoid

After generating the specification:
1. Read `devs/errors-to-avoid-frontend.md`
2. Check each code snippet against the documented patterns
3. Fix any violations before finalizing

## Output

Generate a single implementation file:
```
docs/[feature-name]-frontend-d[N].md
```

Where:
- `[feature-name]` comes from the deliverables document filename
- `[N]` is the deliverable number

## Error Handling

If issues are found:
- **Wrong type**: Suggest correct `/implement-*` command
- **Missing dependencies**: List which deliverables must be completed first
- **Backend not ready**: List which API endpoints are missing

## Tips for High-Quality Frontend

1. **Use the frontend-design plugin**: Describe UI needs in natural language
2. **Check existing patterns**: Look at MomentForm, ValueCard for reference
3. **Mobile-first**: Start with mobile layout, enhance for desktop
4. **Accessibility**: Include ARIA labels, keyboard navigation
5. **Loading states**: Always show feedback during async operations
6. **Error handling**: Graceful degradation with clear error messages
